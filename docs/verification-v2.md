## 測試結果

- **PostgreSQL 與 API** 共 146 項通過，涵蓋 115-1 初選與加退選中的路徑接續試排、正式提交、原鍵重送及 MP4 錄音解碼。AT-11 和 AT-24 使用 Gemini 介面模擬，涵蓋有效回應、轉寫不完整及服務失敗。測試產生兩則第三方棄用警告。
- **瀏覽器與前端** 13 項 Playwright 測試通過，TypeScript 和 Vite 產出成功。使用 Chromium 測試三校查詢與來源、同名選班、回應遺失後以原鍵重送、路徑接續試排與錄音介面。麥克風使用 Chromium 測試裝置，朗讀以瀏覽器呼叫驗證。另以映射到本機的 HTTP 網域驗證允許來源的登入、重送鍵與文字加選，未列入允許清單的網域回 `403`。
- **Mailpit** 寄送課表 API 回 `201`。Worker 遇 TCP 拒絕後進入重試，第二次成功標為 `SENT`。本機信箱收到含週課表時段與教室的信件。快照的正式與待分發時段、同鍵去重和分發摘要由資料庫測試覆蓋。
- **資料庫升級** 新資料庫可套用 `0001 → 0004`。從 `v1.0.0` 升級後重跑 seed，原有登記、選課、通知、冪等資料和時段逐列比對相同。另驗證 `0003 → 0004` 保留舊學期選課，新 115-1 班別沿用原教室、名額及先修條件。
- **效能** 4 核心及約 3.8 GiB RAM，1,000 個班別及 20 個並行查詢。暖機 25 次、量測 200 次，p50 為 312.74 ms，p95 為 457.59 ms，低於需求的 500 ms。查課及有效名額的 SQL 與執行計畫已記錄。[效能數據](v2-performance.json) · [SQL 與 EXPLAIN ANALYZE BUFFERS](v2-explain.txt)
- **部署檢查** 8 項腳本測試、Shell 語法及 Compose 設定檢查通過。AT-13 的 Docker 冷啟與重啟仍需有 daemon 權限的環境。

## 修正的問題

- 讀取本人選課時，分發公布可能落在原本分開的兩次查詢之間。統一使用週課表的正式及待分發快照。
- 本機啟動若遇到目前帳號無法讀取的 `.env`，會以程序環境變數及預設值載入設定，避免啟動時中止。
- 本機啟動 Mailpit 時一併設定 SMTP 主機、連接埠與驗證方式，避免讀到 Gmail 帳密或 TLS 設定。
- 身分或學期缺少時，助理的公開查課來源改為可直接開啟的課程入口。
- 系所查詢在三校同名時依學期與校別比對。校名縮寫和專題課號分開辨識，大小寫及全形輸入共用正規化。
- 網路斷線後可用原鍵重送文字與音訊。非 JSON 錯誤回應或代理拒收時，助理顯示文字錯誤並保留可重送的請求。
- 語音片段若靜音、解碼失敗、逾時或供應端回傳未完成的文字，在選課流程前回覆錯誤。
- 補上 MP4 尾端索引的解碼支援。以 8 秒 AAC 錄音重現並驗證。
- 選課助理會沿用已選研究方向，自動勾選本期符合條件的班別。初選確認後顯示待分發，加退選確認後更新正式課表。
